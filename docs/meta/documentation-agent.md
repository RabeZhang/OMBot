# Documentation Maintenance Agent

**验证状态**

- 文档维护规则：已定义
- 评分维度：已定义
- 执行方式：当前由人工 + Codex 共同维护

**核心理念**

- OMBot 需要一个专门维护文档系统的“文档 Agent”视角。
- 这个 Agent 不负责发明新设计，而负责：
  - 识别已废弃内容
  - 识别实现与文档不一致的地方
  - 识别缺少主文档入口的功能
  - 按产品和架构维度给文档体系打分

**当前实现方式**

文档维护 Agent 的工作流程：

1. 扫描 `src/`、`config/`、`workspace/`
2. 对照 `docs/Agent.md` 模块索引
3. 识别：
   - 缺文档模块
   - 过时文档
   - 文档与代码不一致内容
4. 更新对应模块文档
5. 删除或合并已经失效的旧文档

评分维度：

- 产品清晰度：`1-5`
  - 这个文档是否清楚说明用户看到的能力与限制
- 架构清晰度：`1-5`
  - 这个文档是否清楚说明模块边界与依赖关系
- 实现对齐度：`1-5`
  - 这个文档是否与当前代码主链一致

评分解释：

- `5`：清晰、稳定、与代码一致
- `4`：基本清晰，少量细节待补
- `3`：可用，但仍混有旧设计或边界不清
- `2`：多处过时，误导风险明显
- `1`：基本不可作为当前参考

维护动作：

- 当实现发生重大变化时：
  - 先更新模块文档
  - 再更新 `product/current-state.md`
  - 再检查 `Agent.md` 索引是否需要调整
- 当某条设计被推翻时：
  - 删除旧文档
  - 或在新主文档里明确其已废弃
- 当新增模块时：
  - 必须新增对应模块目录文档
